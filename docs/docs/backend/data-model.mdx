# Data model (mono-monolith)

## Identity

| Table | Purpose |
|---|---|
| `tenants` | Organizations |
| `users` | Global users |
| `roles` / `permissions` / `role_permissions` | RBAC catalog (system + tenant roles) |
| `memberships` | User ↔ tenant + role |
| `invitations` | Invite tokens |
| `auth_connections` | SSO links |
| `user_mfa` | TOTP secrets |
| `api_keys` | Hashed `aham_…` keys |
| `scim_tokens` | SCIM bearer hashes |
| `audit_events` | Auth/admin audit |

## Billing

| Table | Purpose |
|---|---|
| `features` | Feature flags / capabilities (incl. `catalog`) |
| `plans` / `plan_features` | Plan catalog |
| `subscriptions` | Tenant subscription state |
| `entitlement_snapshots` | Cached entitlements |
| `entitlement_overrides` | Operator overrides |

## Catalog (showcase)

| Table | Notes |
|---|---|
| `categories` | `TenantScopedMixin`; unique `(tenant_id, name)`; Postgres RLS |
| `items` | `TenantScopedMixin`; `sku`, `status`, `price`, `currency`, `category_id`; unique name/sku per tenant; RLS |

Mutating catalog routes use `require_feature("catalog")`.

## Messaging (Kafka layouts)

| Table | Purpose |
|---|---|
| `outbox_messages` | Transactional outbox (`platform_kit.messaging`) |

## Alembic

- Per service: `alembic.ini` + `alembic/env.py`
- Loads models via `load_models("core_api", include_messaging=settings.kafka_enabled)`
- `compare_type=True`
- **`mono-monolith`** includes an initial revision covering identity, billing, and catalog (+ RLS on `categories` / `items`)
- Fresh Copier outputs still start with empty `versions/` — run `uv run dx db revision <svc> -m "..."` after modules exist, or copy from the example
- Docker entrypoint runs `alembic upgrade head` when `RUN_MIGRATIONS=true`

Tests often enable `DB_AUTO_CREATE` for speed; production must use migrations (`DB_AUTO_CREATE` forbidden in prod).
