# MSW mocks

Enable with:

```bash
VITE_AUTH_MODE=dev
VITE_USE_MOCKS=1
pnpm mocks:init   # writes public/mockServiceWorker.js once
pnpm dev
```

Bootstrap: `apps/web/src/lib/mocks.ts` starts the worker when the flag is set.

## Handlers

Feature-local `*.handlers.ts`, registered from `lib/mocks.ts`:

| Module | Handlers |
|---|---|
| Catalog | `items.handlers.ts`, `categories.handlers.ts` |
| Admin | `users.handlers.ts`, `roles.handlers.ts`, `billing.handlers.ts` |

- In-memory store keyed by `X-Tenant-ID` / stored tenant
- Seed data for happy-path UI (items, categories, members, roles, plans)
- CRUD / invite / checkout / cancel shapes match the live APIs

There is **no silent API fallback** — without MSW (or a live API), requests fail normally.

## When to use

- UI development without Docker/backend
- Storybook / Vitest with handler overrides
- Pair with `auth_mode=dev` so login does not hit `/auth/*`
